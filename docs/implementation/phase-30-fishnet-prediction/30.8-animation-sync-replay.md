# 30.8 NetworkAnimationSync Tick-Anpassung

**Commit:** `fix(phase-30): 30.8 NetworkAnimationSync Replay-Guard`
**Branch:** `fix/animation-sync-replay`

---

## Ziel

`NetworkAnimationSync` vor ungewollten State-Changes waehrend Reconcile-Replay schuetzen. Waehrend FishNet's Reconciliation werden mehrere `[Replicate]`-Ticks im Schnelldurchlauf abgespielt — dabei duerfen Animations-State-Changes NICHT als Netzwerk-Events gebroadcastet werden.

---

## Anweisungen

### 1. Replay-Guard in NetworkAnimationSync

In `NetworkAnimationSync.cs`:

```csharp
/// <summary>
/// Flag das anzeigt ob aktuell ein Reconcile-Replay laeuft.
/// Waehrend Replay duerfen keine Netzwerk-Events gesendet werden.
/// </summary>
private bool _isReplaying;

/// <summary>
/// Wird von NetworkCharacterDriver gesetzt waehrend Reconcile-Replay.
/// </summary>
public void SetReplayMode(bool isReplaying)
{
    _isReplaying = isReplaying;
}
```

### 2. State-Change Guards

Ueberall wo `NetworkAnimationSync` Animation-State-Changes broadcastet:

```csharp
private void OnAnimationStateChanged(CharacterAnimationState newState)
{
    // Waehrend Replay KEINE Netzwerk-Events senden!
    if (_isReplaying) return;

    // ... bestehender Broadcast-Code ...
}
```

### 3. NetworkCharacterDriver: Replay-Flag setzen

In `NetworkCharacterDriver.cs`, innerhalb der `[Replicate]` Methode:

```csharp
[Replicate]
private void PerformReplicate(MoveReplicateData input, ReplicateState state,
    Channel channel = Channel.Unreliable)
{
    // Replay-Guard fuer AnimationSync
    var animSync = GetComponent<NetworkAnimationSync>();
    if (animSync != null)
        animSync.SetReplayMode(state.IsReplayed());

    // ... Simulation ...

    // Replay-Guard zuruecksetzen (fuer Sicherheit)
    if (animSync != null)
        animSync.SetReplayMode(false);
}
```

**Alternative:** Das Replay-Flag kann auch ueber `ReplicateState` direkt in der AnimationSync geprueft werden, falls ein globaler Zugriff auf den aktuellen Replay-Status verfuegbar ist.

### 4. TimeManager.Tick Verifizierung

Pruefen ob `NetworkAnimationSync` bereits `TimeManager.Tick` korrekt verwendet:
- Animation-Events muessen mit dem richtigen Tick assoziiert sein
- Falls noch lokale Tick-Counter verwendet werden → auf `TimeManager.Tick` umstellen

### 5. Parameter-Sync waehrend Replay

Animator-Parameter-Updates (Speed, IsGrounded, etc.) waehrend Replay sind **akzeptabel** — sie veraendern nur den lokalen Animator-State und werden nicht gebroadcastet. Nur **ObserversRpc**-Aufrufe muessen im Replay unterdrueckt werden.
