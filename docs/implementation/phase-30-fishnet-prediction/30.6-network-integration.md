## Anweisungen

### 1. PlayerController: Driver-aware Update()

```csharp
private void Update()
{
    // Input immer in Update() sammeln (unabhaengig vom Driver)
    UpdateInput();

    // Wenn externer Driver aktiv → NUR Input sammeln, NICHT simulieren
    // FixedUpdate() und NetworkCharacterDriver.OnTick() steuern die Simulation
}
```

### 2. PlayerController: Interne Properties fuer Driver exponieren

Der `NetworkCharacterDriver` braucht Zugriff auf interne Daten:

```csharp
/// <summary>ReusableData fuer externen Zugriff (NetworkCharacterDriver).</summary>
public PlayerMovementReusableData ReusableData => _reusableData;

/// <summary>Input Provider fuer externen Zugriff.</summary>
public IMovementInputProvider InputProvider => _inputProvider;

/// <summary>Aktueller CameraYaw (fuer MoveReplicateData).</summary>
public float CameraYaw => _locomotion?.CurrentCameraYaw ?? 0f;

/// <summary>Ability System Referenz.</summary>
public AbilitySystem AbilitySystem => _abilitySystem;

/// <summary>
/// Index des aktuellen Movement-States fuer Reconcile-Serialisierung.
/// </summary>

/// <summary>
/// Stellt einen Movement-State aus dem Reconcile-Snapshot wieder her.
/// </summary>
public void RestoreMovementState(byte stateIndex)
{
    _movementStateMachine?.RestoreState(stateIndex);
}
```

### 4. PlayerMovementStateMachine: StateIndex Support

Falls noch nicht vorhanden, muss die StateMachine State-Indices unterstuetzen:

```csharp
/// <summary>
/// Gibt den Index des aktuellen States zurueck (fuer Reconcile-Serialisierung).
/// </summary>
public byte CurrentStateIndex
{
    get
    {
        // Mapping von State-Typ auf Index
        // z.B. 0=Idle, 1=Walking, 2=Running, 3=Sprinting, etc.
        return GetStateIndex(_currentState);
    }
}

/// <summary>
/// Stellt den State anhand eines Index wieder her (nach Reconcile).
/// </summary>
public void RestoreState(byte stateIndex)
{
    var targetState = GetStateByIndex(stateIndex);
    if (targetState != null && targetState != _currentState)
    {
        _currentState.OnExit();
        _currentState = targetState;
        _currentState.OnEnter();
    }
}
```

**Hinweis:** Die genaue Index-Zuordnung haengt von der konkreten StateMachine-Implementierung ab. Eine einfache Loesung ist ein Dictionary oder Switch-Statement.

### 5. NetworkPlayer: Motor-Deaktivierung entfernen

In `NetworkPlayer.cs`, Methode `DisableRemotePlayerInput()`:

```csharp
// ALT — Motor fuer Remote-Player deaktiviert:
// _motor.enabled = false;  // ENTFERNEN!

// NEU — Motor bleibt aktiv fuer Spectator-Prediction
// FishNet's [Replicate] steuert Remote-Player ueber state.IsFuture()
```

**Warum?** FishNet Spectator-Prediction nutzt den Motor auch fuer Non-Owner-Player. Der letzte bekannte Input wird wiederholt um die Position bis zum naechsten Server-Update vorherzusagen.

### 6. NetworkPlayer: NetworkCharacterDriver Referenz

```csharp
// Falls NetworkPlayer den Driver referenzieren muss:
private NetworkCharacterDriver _characterDriver;

public override void OnStartNetwork()
{
    base.OnStartNetwork();
    _characterDriver = GetComponent<NetworkCharacterDriver>();
}
```

- Reihenfolge: `NetworkCharacterDriver` NACH `PlayerController` (damit `GetComponent` funktioniert)
