### 3. AttackRuntimeTests

**Datei:** `Tests/Runtime/Core/AttackRuntimeTests.cs`

Benötigt Mock für IHitboxController:

```csharp
private class MockHitboxController : IHitboxController
{
    public bool IsActive { get; private set; }
    public int EnableCallCount { get; private set; }
    public int DisableCallCount { get; private set; }
    public AttackDefinition LastEnabledAttack { get; private set; }

    public void EnableHitbox(AttackDefinition attack)
    {
        IsActive = true;
        EnableCallCount++;
        LastEnabledAttack = attack;
    }

    public void DisableHitbox()
    {
        IsActive = false;
        DisableCallCount++;
    }
}
```

### 4. AttackPersistenceTests

**Datei:** `Tests/Runtime/Core/AttackPersistenceTests.cs`

**Hinweis:** File I/O Tests benötigen temporären Pfad. Für Unit Tests eine Überladung oder Test-Helper verwenden, der in `Application.temporaryCachePath` schreibt statt `StreamingAssets`.

**Testfälle:**

```
AttackPersistence:
- SaveAndLoad_RoundTrip_PreservesData
- Load_NonExistentFile_ReturnsNull
- SaveAll_MultipleAttacks_CreatesFiles
- LoadAll_ReturnsAllValidAttacks
- LoadAll_EmptyDirectory_ReturnsEmptyList
- Delete_ExistingFile_ReturnsTrue
- Delete_NonExistentFile_ReturnsFalse
- Exists_AfterSave_ReturnsTrue
```

**Tipp:** Um StreamingAssets in Tests zu vermeiden, kann `AttackPersistence` eine interne Methode `GetDirectory()` haben, die in Tests überschrieben wird, oder die Tests schreiben nach `Application.temporaryCachePath + "/TestCombatData"` und räumen danach auf.
