# 29.6 LookAt-System Reparatur

> **Commit:** `feat(phase-29): 29.6 LookAt-System Reparatur`
> **Branch:** `feat/lookat-fix` (vom Integration-Branch)

---

## Ziel

Das **LookAt-IK-System** reparieren, das nach dem Phase-28-Refactoring nicht mehr korrekt funktioniert. `CameraTargetProvider` nutzt `Camera.main` — die Ursache des Bruchs muss identifiziert und behoben werden.

---

## Problemanalyse

### Mögliche Ursachen

1. **Camera.main Tag fehlt** — Nach PivotRig-Refactoring hat die Unity Camera-Component möglicherweise kein "MainCamera"-Tag mehr
2. **Transform-Hierarchie** — Camera sitzt jetzt verschachtelt (Root → Yaw → Pitch → Offset → Camera). `Camera.main.transform.position` könnte korrekt sein, aber die Forward-Richtung könnte durch die Hierarchy beeinflusst sein
3. **Timing** — LookAtIK läuft in `OnAnimatorIK()` (nach Animation), PivotRig-Update in `LateUpdate()` → Frame-Versatz

### Diagnose-Schritte

1. **Camera.main prüfen:** Ist `Camera.main` zur Runtime `null`? → Tag-Problem
2. **Position prüfen:** Ist `Camera.main.transform.position` an der erwarteten Stelle?
3. **Forward prüfen:** Zeigt `Camera.main.transform.forward` in die richtige Richtung?

---

## Bestehende Datei modifizieren

### CameraTargetProvider.cs

**Pfad:** `Packages/Wiesenwischer.GameKit.CharacterController.IK/Runtime/Core/CameraTargetProvider.cs`
(oder ähnlicher Pfad — beim Implementieren exakten Pfad prüfen)

#### Fix-Strategie

**Option A (minimal, bevorzugt):** Camera.main Tag sicherstellen + ggf. Forward-Fix

```csharp
public Vector3 GetTargetPosition()
{
    var cam = Camera.main;
    if (cam == null) return _defaultLookTarget;

    // Kamera-Position + Blickrichtung als LookAt-Target
    return cam.transform.position + cam.transform.forward * _lookAheadDistance;
}
```

Zusätzlich sicherstellen, dass die Camera in der PivotRig-Hierarchie den Tag "MainCamera" hat.

**Option B (robuster):** CameraBrain als Quelle statt Camera.main

```csharp
[SerializeField] private CameraBrain _cameraBrain;

public Vector3 GetTargetPosition()
{
    if (_cameraBrain != null)
    {
        Vector3 camPos = _cameraBrain.transform.position;
        Vector3 camFwd = _cameraBrain.Forward;
        return camPos + camFwd * _lookAheadDistance;
    }

    // Fallback auf Camera.main
    var cam = Camera.main;
    if (cam == null) return _defaultLookTarget;
    return cam.transform.position + cam.transform.forward * _lookAheadDistance;
}
```

**Empfehlung:** Option A zuerst versuchen (Tag prüfen/setzen). Falls das nicht reicht → Option B.

## Anweisungen

### Schritt 1: Camera.main Tag prüfen

1. Prüfe in der Playground-Szene ob die Camera-Component den Tag "MainCamera" hat
2. Falls nicht: Tag setzen (im Prefab oder über Script)
3. Die Camera sitzt in der PivotRig-Hierarchie auf dem letzten Kind (Offset-Pivot oder direkt)

### Schritt 2: CameraTargetProvider diagnostizieren

1. Lies den aktuellen Code von `CameraTargetProvider.cs`
2. Prüfe wie `Camera.main` genutzt wird
3. Identifiziere die genaue Ursache

### Schritt 3: Fix implementieren

1. **Falls Tag-Problem:** Tag im Prefab/Szene setzen + ggf. im PivotRig-Setup sicherstellen
2. **Falls Forward-Problem:** CameraBrain.Forward als Quelle nutzen (Option B)
3. **Falls Timing-Problem:** Execution Order anpassen oder auf `LateUpdate`-Daten zugreifen

### Schritt 4: Manuell verifizieren

1. Play-Mode starten
2. Character-Kopf sollte in Kamera-Richtung drehen
3. Bei Bewegung: Kopf leicht in Bewegungsrichtung schauen (Blend)
4. Im Idle: Kopf zur Kamera drehen
