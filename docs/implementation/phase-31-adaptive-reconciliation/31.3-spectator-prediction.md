# 31.3 Spectator Prediction Verbesserung

## Ziel

Spectator-Prediction verbessern: konfigurierbares Predict-Ahead (statt hardcoded 2 Ticks).

## Aenderungen

**Datei:** `Packages/Wiesenwischer.GameKit.Network.FishNet/Runtime/Core/NetworkCharacterDriver.cs`

### Konfigurierbares Predict-Ahead

```csharp
[SerializeField] private int _spectatorMaxPredictTicks = 4;
```

Ersetzt das hardcoded `> 2` in der Spectator-Sektion.

### Spectator Correction — ENTFERNT

**Urspruenglicher Ansatz (fehlerhaft):**
OnSpectatorCorrection erfasste `prePos` (vor Simulation) und `postPos` (nach Simulation).
Das ist `prePos - postPos = -movement` — die volle Tick-Bewegung, NICHT der Reconcile-Error.

**Symptom:** Jeder Tick addierte `-movement` zum Offset → persistenter 1.5-2.5m Offset → Offset-Decay dominierte die visuelle Geschwindigkeit → sichtbarer Stutter mit 5-12:1 Ratio.

**Fix:** OnSpectatorCorrection komplett entfernt. Spectator-Corrections laufen ueber den gleichen `OnReconcileComplete`-Pfad wie beim Owner:
- FishNet reconciled Non-Owner-Objekte via `ReconcileToStates`
- `PerformReconcile` setzt `_didReconcile = true`
- `PerformReplicate(ContainsTicked)` → `OnReconcileComplete`
- Die Goal-Queue interpoliert natuerlich zur korrekten Position

### Spectator Future Prediction (beibehalten)

Non-Owner Objekte nutzen `_lastTickedReplicateData` fuer `state.IsFuture()` Prediction:
- Letzter autoritativer Input wird fuer bis zu `_spectatorMaxPredictTicks` Ticks wiederverwendet
- One-Shot Events (Jump, JumpCut, ResetVertical) werden dabei nicht predicted
