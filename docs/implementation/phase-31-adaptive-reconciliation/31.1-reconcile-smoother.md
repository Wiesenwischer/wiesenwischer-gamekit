# 31.1 ReconcileSmoother Komponente

## Ziel

Einheitliches Visual-Smoothing fuer Netzwerk-Characters. Handhabt BEIDES: Tick-Interpolation (Goal-Queue) UND Reconcile-Correction (Offset-Decay). Einziger Schreiber auf `Transform.position` in LateUpdate — KCC-Interpolation ist deaktiviert.

## Neue Datei

`Packages/Wiesenwischer.GameKit.Network.FishNet/Runtime/Core/ReconcileSmoother.cs`

## Anforderungen

- `[DefaultExecutionOrder(50)]` — VOR CameraBrain (100) und GroundingSmoother (100)
- Serialized Fields:
  - `_snapThreshold` (float, default 2.0) — ab dieser Distanz: hard snap
  - `_correctionRate` (float, default 0.25) — Decay-Rate (25% pro Frame bei 60fps)
  - `_rotationCorrectionRate` (float, default 0.25)
  - `_rotSmoothTime` (float, default 0.033) — Exponential Smoothing Zeitkonstante fuer Rotation
  - `_minCorrectionThreshold` (float, default 0.001) — unter diesem Wert: Zero
  - `_catchupThreshold` (int, default 2) — ab dieser Queue-Tiefe: Catchup
  - `_catchupRate` (float, default 0.25) — Beschleunigungs-Faktor pro Extra-Eintrag
- Public API:
  - `OnPreTick(Vector3 motorPos, Quaternion motorRot, float tickDelta)` — Initialisierung
  - `OnPostTick(Vector3 motorPos, Quaternion motorRot, float tickDelta)` — Goal in Queue pushen
  - `OnReconcileComplete(Vector3 prePos, float preRotY, Vector3 correctedPos, float correctedRotY)` — Reconcile-Error verarbeiten
  - `OnSpectatorCorrection(Vector3 prePos, Vector3 postPos, Quaternion postRot)` — Spectator-Error verarbeiten
  - `ClearOffset()` — Offset auf Zero (hard snap)
  - `Reset()` — Komplett zuruecksetzen (Disconnect)
  - `float SnapThreshold { get; }` — fuer NetworkCharacterDriver
  - `Vector3 CurrentOffset { get; }` — fuer Debug
  - `int QueueCount { get; }` — fuer Debug/Tests
  - `float InterpolationT { get; }` — fuer Tests

## Goal-Queue Architektur

```
_goalQueue      = Motor-Positionen pro Tick (FIFO)
_fromPos/_toPos = aktuelles Interpolations-Segment
_interpT        = Fortschritt im Segment (0=from, 1=to)
_positionOffset = Reconcile-Correction Offset (exponentieller Decay)

Visual = Lerp(_fromPos, _toPos, _interpT) + _positionOffset
```

### Adaptive Queue Drain

Statt Goals hart zu droppen (→ visueller Teleport) wird die Consumption bei Queue-Wachstum leicht beschleunigt:
- `speedMultiplier = 1 + excess * catchupRate` (excess = queueCount - catchupThreshold)
- queue=3 bei defaults → 1.25x, queue=4 → 1.5x
- Visuell: Character bewegt sich kurzzeitig ~25-75% schneller — kaum sichtbar
- HardQueueLimit=8 als Safety fuer extreme Faelle (z.B. Editor-Pause)

### Server-Side Guard

Dedicated Server (`IsServerStarted && !IsClientStarted`) braucht kein Visual-Smoothing.
NetworkCharacterDriver setzt `_smoother = null` → alle Smoother-Aufrufe werden uebersprungen.

## LateUpdate

1. Goal-Queue Interpolation (Lerp von _fromPos nach _toPos, Goals konsumieren)
2. Rotation: Exponential Smoothing via Slerp
3. Offset-Decay: `Mathf.Pow(1 - rate, deltaTime * 60)` — frame-rate-unabhaengig
4. Micro-Jitter: `sqrMagnitude < threshold² → Zero`
5. Final: `transform.position = interpPos + offset`
