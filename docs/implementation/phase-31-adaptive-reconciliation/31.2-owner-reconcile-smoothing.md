# 31.2 Owner Reconcile Smoothing

## Ziel

NetworkCharacterDriver mit ReconcileSmoother verbinden. Bei Reconciliation: pre-reconcile Position speichern, nach Replay den Error berechnen und als Correction-Offset setzen.

## Aenderungen

**Datei:** `Packages/Wiesenwischer.GameKit.Network.FishNet/Runtime/Core/NetworkCharacterDriver.cs`

### Neue Felder

```csharp
private ReconcileSmoother _smoother;
private bool _didReconcile;
private Vector3 _preReconcilePosition;
private float _preReconcileRotation;
```

### OnStartNetwork

`_smoother = GetComponent<ReconcileSmoother>();`

### PerformReconcile — Pre-Snap Position speichern

VOR dem `SetPositionAndRotation()`:
- `_preReconcilePosition = _motor.TransientPosition`
- `_preReconcileRotation = _motor.TransientRotation.eulerAngles.y`
- `_didReconcile = true`

### PerformReplicate — Error nach Replay

Am ANFANG von PerformReplicate, VOR Spectator-Logik und Simulation:
- Check: `_didReconcile && state.ContainsTicked() && _smoother != null`
- `state.ContainsTicked()` = erster nicht-replayed Tick → alle Replays sind durch
- Error = `_preReconcilePosition - _motor.TransientPosition`
- Wenn Error > SnapThreshold → `ClearOffset()` (hard snap)
- Sonst → `SetCorrectionOffset(error, rotError)`
- `_didReconcile = false`

### Warum state.ContainsTicked()?

FishNet's Reconcile-Flow:
1. `PerformReconcile()` — Snap zu Server-State
2. `PerformReplicate(Replayed)` × N — alle Ticks seit Server-Tick replayed
3. `PerformReplicate(Ticked)` — erster neuer Tick

Bei Schritt 3 enthaelt `TransientPosition` die korrigierte Prediction. Der Error ist rein die Reconcile-Korrektur, ohne Vermischung mit aktuellem Tick-Movement.
