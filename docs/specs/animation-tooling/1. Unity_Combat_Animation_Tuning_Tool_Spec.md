# Unity Combat Animation Tuning Tool --- Engineering Specification

------------------------------------------------------------------------

## 1. Zielsetzung

Wir möchten ein Runtime-Tool erstellen, mit dem Animationen für
Combat-Angriffe visuell getuned werden können.

Das Tool soll:

-   innerhalb eines BUILT Unity Games laufen (kein Unity Editor
    notwendig)
-   Animationen visualisieren
-   Timing-Fenster (Hit Frames etc.) anzeigen
-   Attack-Timing in Frames editieren
-   sofortiges Testen ermöglichen
-   Daten persistent speichern (JSON / ScriptableObject Export)

------------------------------------------------------------------------

## 2. Grundlegende Architekturentscheidungen

### 2.1 KEINE Animation Events

**Entscheidung**

Animation Events werden NICHT für Gameplay Timing verwendet.

**Gründe**

-   Animation Events sind Editor-Daten.
-   Runtime Editing schwierig.
-   Merge Konflikte in Clips.
-   Gameplay-Logik wird im Animator versteckt.
-   Tooling wird unnötig komplex.

Stattdessen:

Gameplay Timing ist vollständig Data-driven.

------------------------------------------------------------------------

### 2.2 Animation = reine Visualisierung

Animator wird nur für:

-   Visual Playback
-   Blendtrees
-   State Transitions

verwendet.

Animator entscheidet NICHT:

-   Hit Timing
-   Damage
-   Gameplay Events

------------------------------------------------------------------------

### 2.3 Gameplay Anchor = Attack Start im Code

Anchor Zeitpunkt:

attackStartTime = Time.time

Dieser Zeitpunkt ist:

-   deterministisch
-   netzwerkfreundlich
-   tool-unabhängig

------------------------------------------------------------------------

### 2.4 Timing wird in Frames gespeichert

**Warum Frames?**

-   Combat Design denkt in Frames.
-   Stabil bei Animation Speed Changes.
-   Intuitiv visualisierbar.
-   Deterministisch.

------------------------------------------------------------------------

## 3. Datenmodell

### AttackDefinition

``` csharp
[Serializable]
public class AttackDefinition
{
    public string attackId;

    public int hitStartFrame;
    public int hitEndFrame;

    public float damage;
}
```

------------------------------------------------------------------------

## 4. Runtime Combat Timing

### Animation starten

``` csharp
attackStartTime = Time.time;
animator.Play("Attack");
```

------------------------------------------------------------------------

### Frame Berechnung

``` csharp
AnimatorStateInfo state =
    animator.GetCurrentAnimatorStateInfo(0);

float normalizedTime = state.normalizedTime % 1f;

int totalFrames =
    Mathf.RoundToInt(clip.length * clip.frameRate);

int currentFrame =
    Mathf.FloorToInt(normalizedTime * totalFrames);
```

------------------------------------------------------------------------

### Hit Detection

``` csharp
if(currentFrame >= attack.hitStartFrame &&
   currentFrame <= attack.hitEndFrame)
{
    EnableHitbox();
}
```

------------------------------------------------------------------------

## 5. Runtime Editor Tool Architektur

Tool läuft im Game als Debug UI.

### Features

-   Animation Preview
-   Timeline Anzeige
-   Frame Marker
-   Hit Window Overlay
-   Live Testing

------------------------------------------------------------------------

### 5.1 Animation Scrubbing

``` csharp
animator.Play("Attack", 0, normalizedTime);
animator.Update(0);
```

------------------------------------------------------------------------

### 5.2 Timeline Darstellung

    |------------------------------------|
    0                                  maxFrames

             [====== HIT WINDOW ======]

------------------------------------------------------------------------

### 5.3 Marker Editing

UI:

-   Slider für Current Frame
-   Button "Set Hit Start"
-   Button "Set Hit End"

------------------------------------------------------------------------

### 5.4 Live Preview

Nach Änderung:

-   Attack neu triggern
-   Hit Window sofort sichtbar

## 10. Häufige Fehler vermeiden

-   normalizedTime direkt als Gameplay Timing nutzen
-   Animation Events für Gameplay Timing
-   Sekunden statt Frames speichern
-   Animator als Combat State Machine verwenden

------------------------------------------------------------------------

## 11. Vorteile dieses Systems

-   deterministisch
-   editor-unabhängig
-   leicht testbar
-   multiplayerfreundlich
-   visuell verständlich
-   tool-first workflow

------------------------------------------------------------------------

Animation (Visual)\
Gameplay Timing (Data)

Dadurch entsteht:

-   maximale Stabilität
-   flexible Tuning Tools
