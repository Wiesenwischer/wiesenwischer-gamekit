# Unity Combat Tool --- AAA Timeline Architecture Specification

------------------------------------------------------------------------

# 1. Zielsetzung

Dieses Dokument beschreibt die Architektur einer professionellen
Timeline UI für das Combat Animation Tuning Tool.

Ziel ist eine visuelle Bearbeitung ähnlich eines Video Editors oder AAA
Designer Tools.

Schwerpunkte:

-   Drag & Resize Hit Windows
-   Frame-basierte Darstellung
-   Stabile Performance
-   Saubere Trennung von UI und Gameplay
-   Erweiterbarkeit für zukünftige Combat Features

------------------------------------------------------------------------

# 2. Grundprinzipien

## 2.1 Timeline ist rein visuell

Die Timeline darf KEINE Gameplay-Logik enthalten.

Sie:

-   visualisiert Daten
-   manipuliert Daten
-   sendet Änderungen an Data Layer

Gameplay bleibt im Combat Runtime System.

------------------------------------------------------------------------

## 2.2 Frame-basierte Darstellung

Timeline basiert vollständig auf Frames.

Warum:

-   Deterministisch
-   Intuitiv für Combat Design
-   Stabil bei Animation Speed Änderungen

------------------------------------------------------------------------

# 3. UI Struktur (High-Level)

Empfohlene Hierarchie:

    TimelineRoot
        BackgroundBar
        FrameMarkers
        CurrentFrameCursor
        HitWindowContainer
            HitWindowRect
                LeftHandle
                RightHandle

------------------------------------------------------------------------

# 4. Coordinate Mapping

Wichtigster Bestandteil.

Umrechnung:

    frame → position
    position → frame

Formel:

    xPosition = (frame / totalFrames) * timelineWidth

Reverse:

    frame = (xPosition / timelineWidth) * totalFrames

------------------------------------------------------------------------

# 5. Current Frame Cursor

Vertikale Linie.

Update Loop:

-   aktuelle Animation Frame berechnen
-   Cursor Position setzen

Pseudo Code:

    cursorX = frameToPosition(currentFrame)
    cursorRect.anchoredPosition = new Vector2(cursorX, 0)

------------------------------------------------------------------------

# 6. Hit Window Darstellung

Hit Window ist ein RectTransform.

Start Position:

    startX = frameToPosition(hitStartFrame)

Breite:

    width = frameToPosition(hitEndFrame - hitStartFrame)

------------------------------------------------------------------------

# 7. Drag Behaviour

HitWindowRect draggable.

Beim Drag:

1.  Maus Delta berechnen
2.  Neue Position setzen
3.  Frame berechnen
4.  Data aktualisieren

Pseudo:

    newFrame = positionToFrame(newX)
    attack.hitStartFrame = newFrame

------------------------------------------------------------------------

# 8. Resize Behaviour

Handles links/rechts.

Left Handle:

-   verändert hitStartFrame

Right Handle:

-   verändert hitEndFrame

------------------------------------------------------------------------

# 9. Frame Step Controls

Buttons:

-   Step +1 Frame
-   Step -1 Frame

Implementation:

    currentFrame += 1
    normalized = currentFrame / totalFrames
    animator.Play("Attack", 0, normalized)

------------------------------------------------------------------------

# 10. Performance Regeln

Sehr wichtig:

-   KEIN Layout Rebuild pro Frame
-   Nur Positionsupdate
-   Keine Instantiate/Destroy während Drag

------------------------------------------------------------------------

# 11. Visual Feedback (AAA UX)

Empfohlen:

-   Hit Window Farbe (z.B. Rot)
-   Hover Highlight
-   Resize Cursor Icons
-   Grid Lines alle 5 oder 10 Frames

------------------------------------------------------------------------

# 12. Erweiterbarkeit

Architektur erlaubt:

-   Multiple Hit Windows
-   Cancel Frames
-   Invulnerability Frames
-   Combo Branch Points
-   Camera Trigger Markers

------------------------------------------------------------------------

# 13. Typische Fehler vermeiden

-   Timeline mit Gameplay Logik koppeln
-   Sekunden statt Frames nutzen
-   normalizedTime direkt speichern
-   Animation Events als Timing verwenden

------------------------------------------------------------------------

# 14. Zusammenfassung

Diese Timeline Architektur:

-   ist stabil
-   data-driven
-   intuitiv bedienbar
-   leicht erweiterbar

Perfekt für ein Combat Designer Tool im Runtime Build.

------------------------------------------------------------------------

END OF SPEC
