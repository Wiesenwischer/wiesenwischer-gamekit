# Unity Combat Animation Visual Tuning Tool --- Visual Sandbox & Timeline Editor Spec

------------------------------------------------------------------------

# 1. Zielsetzung

Dieses Dokument beschreibt die visuelle Erweiterung des Combat Animation
Tuning Tools.

Schwerpunkte:

-   Visuelles Feedback statt Zahlen-basiertes Editing
-   Combat Preview gegen einen Gegner
-   Timeline Editor mit klarer Darstellung von Hit Windows
-   Frame-basierte Bearbeitung
-   Stabilität der Combat Architektur (data-driven Timing)

Das Tool soll es ermöglichen:

-   Animationen realistisch im Kontext zu testen
-   Timing intuitiv zu verstehen
-   Attacken schnell zu iterieren ohne Gameplay-Code zu verändern

------------------------------------------------------------------------

# 2. Grundprinzipien

## 2.1 Combat Sandbox statt reines Editor-UI

Das Tool ist keine reine Timeline-Anzeige.

Stattdessen:

Eine kleine Combat Preview Scene.

Warum:

-   Timing wird erst im Kontext sichtbar
-   Reichweite und Reaktion sind entscheidend
-   Designer brauchen visuelles Feedback

------------------------------------------------------------------------

## 2.2 Animation bleibt Visual Layer

Gameplay Timing kommt aus Daten (Frames).

Animator ist nur verantwortlich für:

-   Animation Playback
-   Visualisierung
-   Blending

------------------------------------------------------------------------

# 3. Visual Tool Layout

Empfohlenes Layout:

    ------------------------------------------------
    |             Animation Preview                |
    |                                              |
    |   Player Character        Enemy Dummy        |
    |                                              |
    ------------------------------------------------

    | Timeline ------------------------------------|
    | 0      10     20     30     40               |
    |        [===== HIT WINDOW =====]              |
    |               ^                              |
    |         Current Frame Cursor                 |
    ------------------------------------------------

    [ Play ] [ Pause ] [ Step +1 ] [ Step -1 ]

    Hit Start Frame: [ slider ]
    Hit End Frame:   [ slider ]

    [ Save ]

------------------------------------------------------------------------

# 4. Combat Preview Scene

Separate Preview Umgebung erstellen.

Struktur:

    CombatPreviewRoot
        PlayerPreview
        EnemyDummy
        PreviewCamera

------------------------------------------------------------------------

## 4.1 PlayerPreview

-   nutzt echtes CombatController System
-   gleiche Animationen wie im Game
-   keine Sonderlogik

------------------------------------------------------------------------

## 4.2 Enemy Dummy

Warum notwendig:

-   Timing ohne Gegner wirkt oft korrekt aber fühlt sich falsch an
-   Hit Feedback sichtbar

Features:

-   Hit Reaction Animation
-   Damage Numbers
-   Debug Hitbox Anzeige

------------------------------------------------------------------------

# 5. Timeline Editor

## 5.1 Frame-basierte Darstellung

Timeline basiert auf:

    totalFrames

Visualisierung:

    |--------------------------------------------|
    0                                         maxFrames

------------------------------------------------------------------------

## 5.2 Current Frame Cursor

Cursor bewegt sich live während Animation läuft.

Technisch:

-   RectTransform Position = currentFrame / totalFrames

------------------------------------------------------------------------

## 5.3 Hit Window Overlay

Rechteck über Timeline:

    startPosition = hitStartFrame / totalFrames
    width = (hitEndFrame - hitStartFrame) / totalFrames

------------------------------------------------------------------------

# 6. Animation Playback Modi

## 6.1 Scrubbing Mode

Animation direkt an Frame positionieren.

    animator.Play("Attack", 0, normalizedTime);
    animator.Update(0);

------------------------------------------------------------------------

## 6.2 Live Play Mode

Normales Combat Verhalten:

    combatController.StartAttack(attackDefinition);

------------------------------------------------------------------------

# 7. Frame Step Controls

Sehr wichtig für präzises Tuning.

Buttons:

-   Step Forward (+1 Frame)
-   Step Back (-1 Frame)

Implementation:

    currentFrame++;
    normalized = currentFrame / totalFrames;
    PreviewAnimation(normalized);

------------------------------------------------------------------------

# 8. Hitbox Debug Visualisierung

Empfohlen:

-   Collider transparent anzeigen
-   Aktiv wenn Hit Window aktiv ist

Option:

OnDrawGizmos oder Runtime Mesh Renderer.

------------------------------------------------------------------------

# 9. Kamera Setup

Feste Kamera verwenden.

Warum:

-   Designer verliert sonst Timing Gefühl
-   Konsistente Bewertung der Attacke

------------------------------------------------------------------------

# 10. Attack Phasen Visualisierung (Optional aber stark empfohlen)

Zeige zusätzlich:

    [ Windup ][ Active ][ Recovery ]

Erhöht Verständnis erheblich.

------------------------------------------------------------------------

# 11. Timeline Editor UX (Video Editor Style)

Ziel:

Hit Window visuell verschieben.

Features:

-   Drag Hit Window
-   Resize durch Ziehen der Kanten
-   Direktes visuelles Feedback

Warum:

-   Zahlen werden weniger benötigt
-   Schnellere Iteration

------------------------------------------------------------------------

# 12. Erweiterbarkeit

Später möglich:

-   Multiple Hit Windows
-   Cancel Frames
-   Invulnerability Frames
-   Super Armor Frames
-   Combo Chains

------------------------------------------------------------------------

# 13. Zusammenfassung

Dieses visuelle Tool kombiniert:

-   Combat Sandbox
-   Frame-basierte Timeline
-   Live Preview

Ergebnis:

-   Hohe Stabilität
-   Schnelles Tuning
-   Intuitiver Workflow
-   Minimale Abhängigkeit vom Animator

------------------------------------------------------------------------
